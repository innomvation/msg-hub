# 메신저 허브 (msg-hub)

디스코드·인스타그램·카카오톡을 **한 창에 모아** 쓰는 데스크톱 메신저 허브. Electron 기반.

기성 통합 메신저(Ferdium, Rambox)가 지원하지 못하는 **카카오톡**까지 한 화면에 넣는 것이 목표다.
세 칸을 **동시에** 띄워 탭 전환 없이 한눈에 본다: `디스코드 | 인스타그램 | 카카오톡`.

## 어떻게 동작하나

| 플랫폼 | 방식 | 비고 |
|---|---|---|
| 디스코드 | 공식 웹(`discord.com/app`)을 `webview`로 임베드 | 정상 로그인, ToS 문제 없음 |
| 인스타그램 | 공식 웹 DM(`instagram.com/direct`)을 `webview`로 임베드 | 정상 로그인, ToS 문제 없음 |
| 카카오톡 | **로컬 DB 복호화**로 읽기 + UI 자동화로 전송 | 본인 PC·본인 계정 로컬 전용 |

> 디코·인스타는 각 서비스의 **공식 웹 화면을 그대로** 띄운다(비공식 API/셀프봇을 쓰지 않아 계정 정지 위험 없음).
> 카카오톡은 웹 클라이언트가 없어, 설치된 PC 카톡의 **로컬 데이터베이스를 복호화해 읽고**(읽기 전용),
> 메시지 전송은 카톡 창을 통한 UI 자동화로 처리한다. **철저히 본인 PC·본인 데이터에 대한 로컬 접근**이다.

### 카카오톡 패널 기능
- 전체 채팅방 목록(최신순, 파일 수정시각 기준 실시간 반영) · 안읽음 뱃지 · 나와의 채팅 상단 고정
- 프로필 사진 · 그룹 발신자 실명 · 메시지(텍스트/사진/동영상 썸네일/이모티콘/링크·선물하기 썸네일) 보기
- 대화 날짜 구분선 · 내 메시지 안읽음(1) 표시
- 텍스트·사진·파일 전송(📎) · 읽음 동기화 토글 · (옵션) LLM 자동응답

## 구조

```
msg-hub/
├── package.json
└── src/
    ├── main.js              # Electron 메인 (창 + 디코 로그인 유지 + 카톡 서버 spawn)
    ├── renderer/
    │   └── index.html       # 3열 UI: 디코·인스타 webview + 카톡 커스텀 패널
    └── kakao/
        ├── kakdb.py         # 카톡 로컬 DB 복호화 + 방 목록/메시지 읽기 (핵심)
        ├── server.py        # localhost HTTP 백엔드 (읽기/전송/자동응답)
        ├── kakvendor/       # 벤더링(MIT): 메모리 키 추출 + SQLCipher v4 복호화
        └── notif.ps1        # 윈도우 알림 읽기(폴백 목록용)
```

## 요구사항
- Windows + 데스크톱 **카카오톡 설치 및 로그인**(읽기/전송 모두 설치된 카톡을 사용)
- Node.js(Electron), Python 3

## 실행

```bash
npm install
pip install -r src/kakao/requirements.txt
npm start
```

## 환경변수(선택 — LLM 자동응답을 쓸 때만)
- `KAKAO_MY_NAME` : 본인 카톡 표시이름(내 메시지 구분용). 기본값 `나`.
- `KAKAO_LLM_ENV` : 자동응답 LLM용 `.env` 파일 경로(해당 `.env`에 API 키 등).

## 한계 / 주의
- **본인 PC·본인 데이터 전용**. 다른 사람의 데이터에는 쓸 수 없고, 쓰지 말 것.
- 카카오톡 버전에 따라 복호화 키 체계가 달라질 수 있다(개발 기준 26.8.x, 네이티브 64비트).
- 전송 시 카톡 창이 잠깐 앞으로 나왔다 사라진다(실제 포커스가 필요한 UI 자동화라 불가피).
- 이모티콘 "전송"은 카톡 전용 피커가 필요해 미지원(보기는 됨).
